## Design Context

### Users
Developers working inside IntelliJ IDEA who need to understand an unfamiliar full-stack codebase without leaving the editor. Their primary job is tracing a feature from a React or TypeScript API call to the backend endpoint that handles it, beginning with the current project's FastAPI stack.

### Brand Personality
Precise, mechanical, and trustworthy. Code Visualizer should feel like an engineering instrument: dense enough to be useful, calm enough to inspect, and explicit about what was or was not detected.

### Aesthetic Direction
An IDE-native dark workspace with restrained semantic color for frontend, HTTP, and backend entities. The visualization prioritizes legibility and source provenance over decorative effects, with progressive disclosure for graph detail.

### Design Principles
- Never invent a relationship; unmatched and unsupported results must be visible.
- Begin with major systems, then reveal technologies, files, and endpoints on demand.
- Make every hierarchy level occupy a predictable tree column.
- Preserve context in narrow IntelliJ tool-window widths.
- Keep graph controls secondary to the code relationships.
- Treat loading, empty, and partial-analysis states as first-class states.
